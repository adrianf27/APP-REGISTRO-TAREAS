Guía: del HTML local a web + móvil siempre sincronizados

Dos partes: 1) publicar la web actual en GitHub Pages tal cual está (con localStorage), y 2) el camino para que web y móvil compartan los mismos datos en tiempo real vía Supabase en tu Zimaboard.

Parte 1 — Publicar en GitHub Pages

Qué subir al repositorio (misma carpeta, sin subcarpetas):

  • registro-tareas.html → renómbralo a index.html. GitHub Pages sirve index.html como página de entrada del dominio; si lo dejas con el otro nombre, tu URL sería .../registro-tareas.html en vez de la raíz limpia.
  • manifest.json, service-worker.js
  • icon-192.png, icon-512.png, icon-maskable-512.png, apple-touch-icon.png

Si renombras el HTML a index.html, actualiza dentro de manifest.json el campo start_url de "./registro-tareas.html" a "./index.html" (o simplemente "./").

Pasos:

  1. Crea el repositorio en GitHub (público o privado, da igual para Pages).
  2. Sube los 7 archivos a la rama principal (main), en la raíz del repo.
  3. Settings → Pages → en Source elige la rama main y la carpeta / (root) → Save.
  4. Espera 1–2 minutos; GitHub te da la URL: https://tu-usuario.github.io/tu-repo/.
  5. Abre esa URL desde el móvil → el navegador ofrecerá "Añadir a pantalla de inicio" (Android) o hazlo manualmente desde Compartir (iPhone).

En este punto cada dispositivo sigue guardando sus tareas por separado en su propio localStorage — es la Parte 2 la que unifica los datos.

Parte 2 — Datos centralizados con Supabase en la Zimaboard

2.1 Levantar Supabase autoalojado

  1. En la Zimaboard, instala Docker y Docker Compose si no los tienes.
  2. Clona el repo oficial supabase/supabase, entra en la carpeta docker, copia .env.example a .env y cambia las claves/contraseñas por defecto.
  3. docker compose up -d. Esto levanta Postgres + la API REST/Auth/Realtime de Supabase.
  4. Con Tailscale ya instalado en la Zimaboard, anota su IP de Tailscale (algo como 100.x.x.x) o su nombre de máquina Tailscale (zimaboard.tail-red.ts.net).

2.2 Crear la tabla de tareas

En el SQL Editor del panel de Supabase, crea la tabla con el mismo modelo que ya usa la exportación JSON de la app:

create table tasks (
  id text primary key,
  root_id text not null,
  title text not null,
  category text not null default 'General',
  date date not null,
  status text not null check (status in ('pendiente','finalizada','pospuesta')),
  chain integer not null default 0,
  completed_at timestamptz,
  created_at timestamptz not null default now()
);

alter table tasks enable row level security;
create policy "acceso con anon key" on tasks for all using (true) with check (true);

(La política de arriba es deliberadamente abierta para empezar rápido entre tus propios dispositivos; si más adelante añades varios usuarios, hay que endurecerla con Auth.)

2.3 Cómo llegan los dispositivos hasta la Zimaboard — el punto crítico

Tailscale crea una red privada: solo los dispositivos que tengan la app Tailscale instalada y con sesión iniciada en tu misma red (tailnet) pueden alcanzar la Zimaboard. Esto cambia según desde dónde uses la app:

  • Si instalas Tailscale también en el móvil y el portátil: perfecto, usan la URL Tailscale de la Zimaboard directamente, tráfico cifrado de punto a punto, nadie más lo ve.
  • Si quieres que la web en GitHub Pages (que la visita cualquier navegador normal, sin Tailscale) llegue a Supabase: necesitas Tailscale Funnel, que expone un servicio de tu tailnet como una URL HTTPS pública (https://zimaboard.tu-tailnet.ts.net), sin depender de que el dispositivo tenga Tailscale instalado. Se activa con tailscale funnel 8000 on (ajusta el puerto al que use la API de Supabase, normalmente el 8000 o 54321 según la config).

Para tu caso (web en GitHub Pages + PWA instalada en el móvil), lo más simple es activar Funnel sobre el puerto de la API de Supabase: así cualquier dispositivo con la URL pública llega a tus datos, sin instalar nada extra.

2.4 Conectar la app a Supabase en vez de localStorage

En el HTML, sustituye las funciones load() y save() por llamadas a la API REST de Supabase (usando fetch, sin necesidad de librerías):

const SUPABASE_URL = 'https://zimaboard.tu-tailnet.ts.net'; // o tu URL de Funnel
const SUPABASE_ANON_KEY = 'tu-anon-key-del-.env';

async function load() {
  const res = await fetch(`${SUPABASE_URL}/rest/v1/tasks?select=*`, {
    headers: { apikey: SUPABASE_ANON_KEY, Authorization: `Bearer ${SUPABASE_ANON_KEY}` }
  });
  tasks = await res.json();
}

async function saveTask(task) {
  await fetch(`${SUPABASE_URL}/rest/v1/tasks`, {
    method: 'POST',
    headers: {
      apikey: SUPABASE_ANON_KEY,
      Authorization: `Bearer ${SUPABASE_ANON_KEY}`,
      'Content-Type': 'application/json',
      Prefer: 'resolution=merge-duplicates'
    },
    body: JSON.stringify(task)
  });
}

La idea general: cada vez que el código actual llama a save() (al añadir, completar, posponer, editar o borrar una tarea), en vez de escribir todo el array en localStorage, llamas a saveTask() solo con la tarea que cambió (o a un DELETE para eliminar). Y load() deja de leer localStorage para pedir los datos a Supabase al abrir la app.

2.5 "Siempre actualizado" entre dispositivos

Con eso ya tienes un dato compartido: abres desde el móvil o el portátil y ambos leen/escriben la misma tabla. Si además quieres que, con la app abierta en dos sitios a la vez, los cambios aparezcan solos sin recargar, Supabase Realtime permite suscribirte a cambios de la tabla (supabase-js, con .channel('tasks').on('postgres_changes', ...)) — esto ya es un paso más avanzado, y tiene sentido añadirlo una vez lo básico (leer/escribir contra Supabase) esté funcionando y probado.

2.6 Orden recomendado para no romper nada

  1. Levanta Supabase y crea la tabla (2.1–2.2) sin tocar la app todavía.
  2. Activa Funnel y prueba la API con una petición de prueba (por ejemplo desde el navegador o curl) antes de tocar el HTML.
  3. Cambia load()/save() en una copia del HTML, pruébalo en local.
  4. Cuando funcione, sube esa versión al repositorio de GitHub — se actualiza sola tanto la web como la PWA instalada (gracias al service worker, que la refresca en segundo plano).
